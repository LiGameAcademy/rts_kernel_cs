# 固定站位战斗：数值与执行阶段

Combat目录提供纯数值规则和StationaryCombat执行阶段；后者尚未接入RtsMatch、主游戏或聚合快照。现有移动实现、原Match事件与v14存档没有改动。

- WeaponDefinition / CombatDefinition是只读配置，公开入口再次Validate，record的with不能绕过校验。
- CombatTiming将定点秒向上取整为逻辑帧。上限3600秒，TickRate为1–240；运行时应保存绝对帧截止时间。
- CombatDice使用调用方对局独占的DeterministicRng，骰子为闭区间[1,Sides]，拒绝采样避免模偏；合法出手才调用。零骰不消耗随机，查询与伤害计算不推进随机流。
- CombatDamageRules保留本项目7×7攻防倍率及护甲公式，返回只读计算结果，不直接扣血。它不代表原作所有版本或英雄、Buff、技能的伤害规则。

伤害顺序：基础伤害+骰子 → 攻防倍率 → 护甲 → 正伤不足1取1。护甲系数按1-(0.06×armor)/(1+0.06×abs(armor))计算。0.06及倍率由分数转32.32，逐次乘除向零截断；因此结果与旧double存在细微差异。零及已截成零的极小伤害不触发最低伤害。比如160伤害、10护甲得到100+480/2^32，而不是精确100；-10护甲得到220-480/2^32。

输入域：基础伤害0–1,000,000；骰数0–64；骰面1–1,000,000；生命(0,1,000,000,000]；护甲±1,000,000；射程0–1,000,000且最小不大于最大；冷却1–864,000帧且前摇0–冷却。最大掷骰结果65,000,000，乘最大倍率2和小于2的护甲系数后仍在32.32域内。未知类型及越界配置明确拒绝，不静默回退。

验证：`dotnet run --project tests/Rts.Kernel.Tests -c Release -- --combat-rules`；完整回归入口仍为`./Test.ps1`。功能检查通过不等于现有移动或完整战斗性能通过。

## 执行阶段（#149）

StationaryCombat按实例拥有生命、攻击目标、前摇/冷却绝对帧、出手ID、事件序号与RNG。AddCombatant在帧间登记唯一实体ID和配置；位置与所属玩家通过Advance(frame, entities, commands)的只读实体视图输入，模块不储存或修改它们。新登记单位从下一帧参与；死亡ID不能重新登记，普通Idle不自动反击。

Advance必须逐帧调用，输入必须为完整、合法且不重复的实体视图，存活战斗参与者速度必须为零。本阶段只支持普通单位；不同OwnerId视为敌对，不实现联盟与中立阵营规则。射程按中心距离平方精确比较，边界包含，不引入身体半径或追击容差。调用者负责实体生命周期、命令准入和未来帧调度；本API只接收本帧到期命令，不声称已有网络输入或命令队列。

一帧顺序：校验输入 → 按玩家/序号/输入顺序执行命令 → 统一收集有效出手 → 按攻击者ID扣血 → 按受害者ID完成死亡清理。有效出手收集后，不因攻击者在同帧死亡而撤销，双方可以互杀。集火仍消费已承诺出手的骰子，实际扣血截到剩余生命；首次致命出手拥有击杀归属，每个目标只发一次死亡。

冷却从开始前摇占用。Stop和有效换目标先于当帧出手、取消未生效前摇，但保留NextAttackFrame；新目标需要等余下冷却后完整前摇。同目标重复命令不修改前摇。冷却等于前摇时，旧出手完成后可在同帧开始下一前摇，每单位每帧仍最多一击。Stop持续到新有效命令；拒绝命令保留旧意图。目标离场、死亡、变为同主或越界结束意图，不追击或自动重获目标。

ReadCombatants与帧结果是独立只读数据。死亡仅退出战斗参与，保留不可再用的墓碑状态；实际RtsMatch实体移除及视图生命周期由后续接入处理，不让冻结移动模块读取另一套生命状态。本批没有快照恢复，不能用JSON诊断摘要冒充支持的存档。

验证入口：`dotnet run --project tests/Rts.Kernel.Tests -c Release -- --combat-execution`。完整Test.ps1包含本项。`--combat-profile 24|300|500`保留600帧全部时长及状态/事件指纹；指纹在计时区间外计算，只是诊断数据。

运行时探针见experiments/StationaryCombat/Run-Probes.ps1，需要显式Godot可执行文件与证据输出目录。它串行启动六个独立冷进程，在实际Godot Debug程序集和CLI Release中执行同一规则，记录原始首轮并核对指纹。探针在Ready中推进逻辑帧，测量的是战斗Advance阶段，不能代替含渲染与交互的整个Godot帧预算或黑盒场景。
